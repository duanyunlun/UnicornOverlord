# MOD 校准记录

## 校准对象

- 参考站点：[Melisandre](https://melisand.re/)
- 站点目标：欧美版 v1.05，Title ID `010069401ADB8000`，Build ID `C841FFE2717FF03A13990480C51DA73F091C04FA`
- 本项目目标：亚洲中文版 v1.0.5，Title ID `010054B01AD92000`，Build ID `9C3116F0333EA157526612D17354B3755737C4F2`

校准只读取仓库内的 ROM 与主程序副本。网站 ZIP、解压结果和比较中间文件位于已忽略的 `.codex-melisandre-work/`，不会提交，也没有写入原始 XCI 或存档。

编辑器以版本配置承载 Title ID、Build ID 和代码模板。下表的字段配置在亚洲版与欧美版之间共享；代码型模块分别保留两版实测模板，不能用固定偏移规则临时换算。

## 已确认的版本差异

欧美版数据不能整条覆盖到亚洲版。以据点记录为例，网站写入 16 字节完整记录；亚洲版有 8 条记录在第 9 至 12 字节保存了不同的附加值。直接使用网站 ZIP 会将这些值覆盖为欧美版的 `0`。后续据点编辑器只能修改记录前 4 字节的职业 ID，或按亚洲版原记录重建完整写入。

采矿表的地址和 63 条原始记录一致，但网站在只调整藏宝图权重的样本中，同时把部分一次性掉落的 `max per run` 从 `1` 写成 `999`。本项目不能继承这一行为，藏宝图和其他一次性物品必须保留原上限。

商店并不是每个地图地点各自保存一份完整库存。科尔尼亚武具店的 211 个地点可见条目实际指向 33 组库存记录，同一条地址可能被多个地点引用。编辑器保留地点视角方便筛选，并对这类记录显示“共享库存”；生成器按实际地址写入，不能为了让列表看起来独立而复制或推测新槽位。普通武具店使用金币全局价格表，补给店、黑市以及神圣碎片/斗技场兑换所的数据和货币语义不同，必须分别校准后再接入。

代码补丁的情况与数据表不同。战斗预览、开战被动限制、六人编队和角色随机化按函数语义、附近指令与分支目标逐点重定位；不能因为某些数据表地址相同，就直接替换欧美版 Build ID。开战被动限制的核心判定位于两版相同地址，但标记分支相差 `0x10`，因此仍分别保留模板。

## 接入准则

1. 数据表模块按亚洲版原始记录生成，只改用户明确选择的字段。
2. 代码模块必须先定位亚洲版函数，并核对每个写入点的原指令和分支目标。
3. 角色、技能、职业和物品名称必须以亚洲中文版资源建立 ID 映射，不以欧美名称顺序作为依据。
4. 文本模块只处理用户所选语言 CPK 的副本，不打包上游 FMS，也不跨语言替换整张表。
5. 网站不能提供完整映射时，直接从亚洲版 `main.dec` 和中文 CPK 数据表反推；未确认的子字段保持禁用，不生成猜测性写入。

## 名称与编辑界面

技能下拉覆盖网站实际使用的 441 个技能。英文名与英文说明取自英文版 `UcSkillList.fms`，日文名与日文说明取自日文本体同表，简体中文名与说明取自亚洲版同表；三份 FMS 均以技能 ID `28–468` 对应的固定索引逐项校验后生成资源。英文说明源来自 [UnicornOverlordTextFixes](https://github.com/ChthonVII/UnicornOverlordTextFixes) 删除前的 `d0e3af0` 历史版本，该文件基于英文游戏文本并包含当时的技能说明修正。主动/被动不是用户可改字段：界面以橙色主动标签或青色被动标签显示固有类型，生成器按所选技能在亚洲版原始记录中的 AP/PP 槽决定写入 `+0x0A` 或 `+0x0C`，避免把被动技能消耗写进 AP。

本地化术语优先采用对应版本游戏资源中的原文；游戏资源没有编辑器字段时，再采用 ATLUS 官方英文页面和技巧指南中的 `Units`、`Renown`、`Class Types`、`Active Skills` 等术语。仍无官方对应项的纯编辑器用语采用通行软件术语，并与游戏原文来源分开记录，不把自行翻译描述为官方译名。

职业技能表的首个主动技能位于职业记录 `+0x04`，首个被动技能位于 `+0x34`，首项等级固定为 1；后续三项按“等级、技能 ID”成对保存。AP 位于 `+0x20` 起的四个 32 位槽，PP 位于 `+0x50` 起的四个槽。界面按主动/被动分别提供名称列表，但无法从现有数据严格证明所有跨职业动画组合都安全，因此对不兼容动画保留明确警告。

## 文本编辑器校准

上游 [UnicornOverlordTextFixes](https://github.com/ChthonVII/UnicornOverlordTextFixes) 的 `uo1.05_mod2.11` 只包含英语 1.05 修复后的 `UcFactorList.fms` 与 `UcScriptMsgConv.fms`，不是可跨语言套用的补丁格式。简中与英语的 Factor 表均为 624 项；Script 表均为 489,999 项，但非空索引集合不同，因此只能复用索引结构，不能用英语整表替换中文。

网站默认修复涉及 Factor 索引 95 和 Script 的 24 个索引。逐项比对表明简中对应文本已经正确，包括索引 95 的“敌方数量不多于 3”和索引 74193 的“盾装重击”。本项目不向中文套用英语修复文字，也不打包上游二进制 FMS。

本地以 `cricodecs 1.2.0` 对 `Unicorn_CN.CPK` 副本完成替换、列目录、反向导出和 FMS 解析：未修改 FMS 的自研读写器输出 SHA-256 与输入相同；测试索引 95 的修改能从成品 ZIP 内 CPK 精确读回，未修改的对话表仍可解析。该结果只证明归档结构可静态往返，尚不能代替 Astris 中的实际显示与存取验证。
