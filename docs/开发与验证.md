# 开发与验证说明

## 技术栈

- .NET 10
- Avalonia 12.1.1
- Avalonia Fluent 浅色主题

项目不再依赖 WPF，可在 Windows、macOS 和 Linux 上构建。文件选择使用 Avalonia `StorageProvider`，程序入口和窗口均采用 Avalonia 原生实现。

## 中文数据

- `info/item.txt`：物品名称映射，来自原项目 0.13 公开发行包。
- `info/kind.txt`：武器、盾牌和饰品的存档状态映射，来自原项目 0.13 公开发行包。
- `info/class.txt`：从游戏 v1.0.5 简体中文资源 `UcClassList.fms` 导出。
- `info/skill.txt`：441 个实际使用技能的中英文名称、主动/被动类型与亚洲版原始数值。
- `info/classmod.txt`：73 个职业的成长、AP/PP、主动/被动技能和习得等级原始值。
- `info/fortmod.txt`、`info/minemod.txt`、`info/shopmod.txt`：亚洲版主程序副本中已校准记录的原始值，用于切换条目时恢复正确默认值。
- `info/name.txt`：从游戏 v1.0.5 简体中文资源 `UcCharaList.fms` 导出。

用于验证的游戏版本标题 ID 为 `010054B01AD92000`。基础程序与 v1.0.5 更新合并后，从中文 CPK 中导出 FMS；FMS 转换前后的二进制往返校验一致。

## 本地验证边界

ROM、存档、Keys 和 Firmware 不进入仓库。以下目录已加入 `.gitignore`：

- `.tools/`：本地提取和转换工具
- `.testdata/`：ROM 与存档测试副本
- `.extracted/`：提取出的中间数据

验证必须遵循以下规则：

1. 先把原始 ROM 和存档复制或克隆到 `.testdata/`。
2. 提取、打开和保存操作只针对仓库内副本。
3. 验证结束后比较原文件与初始副本的大小、修改时间或哈希。
4. 禁止提交 Keys、Firmware、ROM、存档或完整提取数据。

## 库存与角色操作

存档为物品和装备共预留 3800 条记录，并非 255 条。批量操作会先计算剩余容量；容量不足时不写入任何记录。单项和批量数量均限制为 1 到 999。

“全消耗道具”只补齐 ID 8–69、71、73–171 中已有名称的数据，包括常规消耗品、素材与礼物。货币、通行证、钥匙、藏宝图、纹章、剧情手记、调试项和占位项不会自动添加。“一键添加所有装备”只为当前没有的装备 ID 新增一条记录，不删除或覆盖已有装备。

角色文件操作含义如下：

- 导出角色：把当前选中角色保存为 464 字节的 `.uocd` 文件。
- 替换角色：读取 `.uocd` 并覆盖当前角色，同时保留当前存档内的角色 ID。
- 新增角色：读取一个或多个 `.uocd`，分配新 ID 后追加到角色列表。

## MOD 工作区

主窗口按数据落点划分为两个顶层工作区：

- “存档编辑”使用蓝灰色工作区标识，包含概览、角色、物品、装备和编队；打开、另存为和保存存档固定在窗口底部状态栏上方。
- “MOD 制作”使用绿色工作区标识，玩法补丁与文本编辑器共用左侧模块列表，不再使用“玩法 MOD / 文本 MOD”二级标签；目标版本固定在窗口顶栏，当前模块对应的导出按钮固定在窗口底部操作栏，不复用存档保存按钮。

顶层工作区标签与各自的内容标签直接相邻，文件路径、模块选择、来源和修改数量等状态统一显示在底部状态栏。表单中的字段名称统一使用半粗体，说明文字、列表内容和当前值保持常规字重。全局只保留编辑器语言设置。切换到 MOD 制作后，存档操作栏不再显示；此时按下存档快捷键也会被拦截，避免把“保存存档”和“导出 MOD 包”误认为同一操作。

角色亲密度记录保存的是存档角色实例 ID；界面先用该 ID 定位角色记录，再通过角色记录的名称 ID 和 `info/name.txt` 显示角色名。角色页的等级、经验值及十项属性加成使用三列四行紧凑布局，角色文件按钮简写为“导出 / 替换 / 新增”，完整行为说明保留在悬浮提示中。主要滚动区域使用自动隐藏滚动条，并在内容右侧预留安全间距，避免滑块覆盖输入框或列表文字。

MOD 页参考 Melisandre 的功能分区，接入十个 ExeFS 模块：技能、战斗预览、战斗计时器、角色随机化、职业、据点、采矿、商店、六人编队和类型克制。每个模块都可独立勾选，右侧参数配置在版本间共享。

“文本 MOD”页接入独立的 RomFS/CPK 工作流。用户必须选择自己游戏版本对应语言的 CPK 副本与 `cricodecs` 可执行文件；编辑器从归档中按实际条目路径定位并导出 `UcFactorList.fms`、`UcScriptMsgConv.fms`，不假定两张表在所有版本中的 CPK 序号固定。界面只实例化最多 500 条搜索结果，避免一次性创建 489,999 个 Avalonia 行对象。

文本语言与游戏版本在文本页分别选择。简体中文使用 `Unicorn_CN.CPK`，欧美英语使用 `Unicorn_US.CPK`；导出包的 Title ID 由文本页目标版本决定。编辑时只改变字符串内容，不允许增删、重排索引或修改每项的 8 字节属性。保存会重建 UTF-8 NUL 字符串区、16 字节对齐和 `FEOC` 尾部，并提示 `%s`、`%%`、`#(...)`、颜色及斜体等标记是否发生变化。

文本格式依据 [UnicornOverlordTextFixes](https://github.com/ChthonVII/UnicornOverlordTextFixes) 的 1.05 说明和 FMS 样本校准。该仓库提供的是英语修复后的两张完整表，不能直接覆盖中文版；中文版对应的 25 个稳定索引经比对均已是语义正确的中文。因此本工具始终在用户所选语言的原始 CPK 上按索引编辑，不捆绑上游 FMS 或游戏文本。

目标版本下拉框目前提供：

- 亚洲中文版 v1.0.5：Title ID `010054B01AD92000`，Build ID `9C3116F0333EA157526612D17354B3755737C4F2`。
- 欧美版 v1.05：Title ID `010069401ADB8000`，Build ID `C841FFE2717FF03A13990480C51DA73F091C04FA`。

数据表模块共用字段模型和已证明相同的地址；代码模块按版本选择独立模板。导出目录、清单和 pchtxt 的 Build ID 都由版本配置生成，不通过运行时猜测地址。

当前参数范围如下：

- 技能：从 441 项名称下拉选择，主动/被动类型由原始记录决定；可改对应 AP/PP 消耗、双威力、命中、目标范围和首个效果参数。
- 战斗预览：完全隐藏或不完美预览，界面显示各模式的具体行为。
- 角色随机化：按种子生成 63 名剧情角色的互逆置换表，可保持相同转职阶段或混合阶段，只用于新游戏。
- 职业：从 73 个职业名称中选择，可改十项成长、AP/PP、4 个主动和 4 个被动技能及习得等级。职业技能记录步长为 `0x8C`；第一技能固定 1 级，后续三个槽保存技能 ID 与等级。
- 据点：先按 63 个游戏内据点名称筛选，再从该地点的招募位置中选择，共覆盖 248 条记录；职业使用名称下拉选择，生成器只写记录前四字节。
- 采矿：先按五个地区采掘场筛选，再从该地点的原版掉落物中选择，共覆盖 63 条记录；可修改物品、权重、挖掘目标和单局上限，不覆盖地区字段及尾字段。
- 商店：先按地图地点筛选，再选择该武具店的原版商品。当前覆盖科尔尼亚 25 个武具店、211 个地点可见条目和 33 组实际库存记录；共享库存会在条目名称中标记，修改后会影响引用同一记录的地点。补给店、黑市、神圣碎片及斗技场兑换所仍待独立映射，不会混入金币武具店。
- 六人编队：第六人功能和扩编荣誉费用。
- 类型克制：骑兵对步兵、弓兵对飞行、飞龙/狮鹫对骑兵三项倍率。

导出前会检查参数范围和模块间地址冲突。详细证据及仍需运行验证的风险见 [MOD 校准记录](MOD校准记录.md)。

导出包采用 `emulator/contents/<所选版本 Title ID>/<模块>/exefs/main.pchtxt` 结构，仅面向 Astris 等支持 `pchtxt` 的模拟器。Atmosphere 实机需要编译后的 IPS，当前不在导出范围内。

代码型补丁模板位于 `UnicornOverlord/mods/`；数据型补丁由 `ModPatchGenerator` 按参数动态生成。两者都只包含偏移与替换值，不包含游戏本体、RomFS、ExeFS、Keys 或 Firmware。新增写入前必须使用相同 Build ID 的主程序副本验证原值、字段宽度和写入范围。

## 最小验证

```bash
dotnet build UnicornOverlord/UnicornOverlord.csproj --configuration Release
dotnet run --project UnicornOverlord/UnicornOverlord.csproj -- --validate-mods .codex-melisandre-work/validation/all-modules.zip
```

第二条命令会用默认参数分别生成亚洲版和欧美版的全部十个 ExeFS 模块，检查 ZIP 数量、Title ID、Build ID、未替换占位符、技能 PP 写址、职业技能首槽、职业 73 的统一步长、据点/采矿/商店地点级联与默认值加载，以及分阶段/混合随机化确实产生不同置换；欧美版文件名会自动增加 `-western`。

文本模块的开发自检可使用：

```bash
dotnet run --project UnicornOverlord/UnicornOverlord.csproj -- --validate-fms <原始.fms> <往返.fms>
dotnet run --project UnicornOverlord/UnicornOverlord.csproj -- --validate-text-mod <cricodecs> <语言.cpk> <UcFactorList.fms> <输出.zip>
```

第一条输出必须与输入逐字节一致。第二条使用测试性索引修改生成亚洲中文版 RomFS ZIP；需要再次解出 CPK 和 FMS，确认索引变化、另一张表仍可解析且源 CPK 哈希不变。当前 `cricodecs 1.2.0` 已完成此静态往返；重建 CPK 是否被 Astris 游戏进程接受仍需动态验证，不能仅由静态解包结果推断。

界面验证至少覆盖：两大工作区的主题区分和切换、顶层与内容标签相邻、底部操作栏随工作区切换、存档操作只在存档编辑中可见、MOD 工作区拦截存档快捷键、启动、打开存档副本、亲密度角色名随编辑器语言切换、滚动条空闲隐藏且不覆盖字段、职业选择窗口、物品与装备中文名称、保存工作副本以及自动备份。MOD 验证还需覆盖顶栏版本切换、模块导航、参数输入、模块启用状态、ZIP 路径和清单中的版本信息；文本页还需覆盖工具校验、语言文件名限制、两表加载、索引/文本搜索、修改计数、标记提示及 ZIP 导出。
