# 开发与验证说明

## 技术栈

- .NET 10
- Avalonia 12.1.1
- Avalonia Fluent 浅色主题

项目不再依赖 WPF，可在 Windows、macOS 和 Linux 上构建。文件选择使用 Avalonia `StorageProvider`，程序入口和窗口均采用 Avalonia 原生实现。

## 中文数据

- `info/item.txt`：物品名称映射，来自原项目 0.13 公开发行包。
- `info/kind.txt`：武器、盾牌和饰品的存档状态映射，来自原项目 0.13 公开发行包。
- `info/class.txt`：从游戏 v1.0.5 简体中文资源 `UcClassList.fms` 导出。
- `info/name.txt`：从游戏 v1.0.5 简体中文资源 `UcCharaList.fms` 导出。

用于验证的游戏版本标题 ID 为 `010054B01AD92000`。基础程序与 v1.0.5 更新合并后，从中文 CPK 中导出 FMS；FMS 转换前后的二进制往返校验一致。

## 本地验证边界

ROM、存档、Keys 和 Firmware 不进入仓库。以下目录已加入 `.gitignore`：

- `.tools/`：本地提取和转换工具
- `.testdata/`：ROM 与存档测试副本
- `.extracted/`：提取出的中间数据

验证必须遵循以下规则：

1. 先把原始 ROM 和存档复制或克隆到 `.testdata/`。
2. 提取、打开和保存操作只针对仓库内副本。
3. 验证结束后比较原文件与初始副本的大小、修改时间或哈希。
4. 禁止提交 Keys、Firmware、ROM、存档或完整提取数据。

## 库存与角色操作

存档为物品和装备共预留 3800 条记录，并非 255 条。批量操作会先计算剩余容量；容量不足时不写入任何记录。单项和批量数量均限制为 1 到 999。

“全消耗道具”只补齐 ID 8–69、71、73–171 中已有名称的数据，包括常规消耗品、素材与礼物。货币、通行证、钥匙、藏宝图、纹章、剧情手记、调试项和占位项不会自动添加。“一键添加所有装备”只为当前没有的装备 ID 新增一条记录，不删除或覆盖已有装备。

角色文件操作含义如下：

- 导出角色：把当前选中角色保存为 464 字节的 `.uocd` 文件。
- 替换角色：读取 `.uocd` 并覆盖当前角色，同时保留当前存档内的角色 ID。
- 新增角色：读取一个或多个 `.uocd`，分配新 ID 后追加到角色列表。

## 最小验证

```bash
dotnet build UnicornOverlord.slnx --configuration Release
```

界面验证至少覆盖：启动、打开存档副本、角色中文名称、职业选择窗口、物品与装备中文名称、保存工作副本以及自动备份。
