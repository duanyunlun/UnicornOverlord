# 开发与验证说明

## 技术栈

- .NET 10
- Avalonia 12.1.1
- Avalonia Fluent 浅色主题

项目不再依赖 WPF，可在 Windows、macOS 和 Linux 上构建。文件选择使用 Avalonia `StorageProvider`，程序入口和窗口均采用 Avalonia 原生实现。

## 中文数据

- `info/item.txt`：物品名称映射，来自原项目 0.13 公开发行包。
- `info/kind.txt`：武器、盾牌和饰品的存档状态映射，来自原项目 0.13 公开发行包。
- `info/class.txt`：从游戏 v1.0.5 简体中文资源 `UcClassList.fms` 导出。
- `info/name.txt`：从游戏 v1.0.5 简体中文资源 `UcCharaList.fms` 导出。

用于验证的游戏版本标题 ID 为 `010054B01AD92000`。基础程序与 v1.0.5 更新合并后，从中文 CPK 中导出 FMS；FMS 转换前后的二进制往返校验一致。

## 本地验证边界

ROM、存档、Keys 和 Firmware 不进入仓库。以下目录已加入 `.gitignore`：

- `.tools/`：本地提取和转换工具
- `.testdata/`：ROM 与存档测试副本
- `.extracted/`：提取出的中间数据

验证必须遵循以下规则：

1. 先把原始 ROM 和存档复制或克隆到 `.testdata/`。
2. 提取、打开和保存操作只针对仓库内副本。
3. 验证结束后比较原文件与初始副本的大小、修改时间或哈希。
4. 禁止提交 Keys、Firmware、ROM、存档或完整提取数据。

## 库存与角色操作

存档为物品和装备共预留 3800 条记录，并非 255 条。批量操作会先计算剩余容量；容量不足时不写入任何记录。单项和批量数量均限制为 1 到 999。

“全消耗道具”只补齐 ID 8–69、71、73–171 中已有名称的数据，包括常规消耗品、素材与礼物。货币、通行证、钥匙、藏宝图、纹章、剧情手记、调试项和占位项不会自动添加。“一键添加所有装备”只为当前没有的装备 ID 新增一条记录，不删除或覆盖已有装备。

角色文件操作含义如下：

- 导出角色：把当前选中角色保存为 464 字节的 `.uocd` 文件。
- 替换角色：读取 `.uocd` 并覆盖当前角色，同时保留当前存档内的角色 ID。
- 新增角色：读取一个或多个 `.uocd`，分配新 ID 后追加到角色列表。

## MOD 工作区

MOD 页参考 Melisandre 的功能分区，接入十个非文本模块：技能、战斗预览、战斗计时器、角色随机化、职业、据点、采矿、商店、六人编队和类型克制。每个模块都可独立勾选，右侧参数配置在版本间共享；文本编辑器涉及中文 CPK 重封包，不在本阶段范围内。

目标版本下拉框目前提供：

- 亚洲中文版 v1.0.5：Title ID `010054B01AD92000`，Build ID `9C3116F0333EA157526612D17354B3755737C4F2`。
- 欧美版 v1.05：Title ID `010069401ADB8000`，Build ID `C841FFE2717FF03A13990480C51DA73F091C04FA`。

数据表模块共用字段模型和已证明相同的地址；代码模块按版本选择独立模板。导出目录、清单和 pchtxt 的 Build ID 都由版本配置生成，不通过运行时猜测地址。

当前参数范围如下：

- 技能：技能 ID、主动/被动消耗、双威力、命中、目标范围和首个效果参数。
- 战斗预览：完全隐藏或不完美预览。
- 角色随机化：按种子生成 63 名剧情角色的互逆置换表，只用于新游戏。
- 职业：73 个职业的十项成长；职业 ID 1 和 21 另可修改 AP/PP。其他职业的点数/技能表并非统一线性布局，未确认前不写入。
- 据点：1 至 248 号雇佣槽的职业 ID，只写记录前四字节。
- 采矿：63 条记录的物品、权重、挖掘目标和单局上限，不覆盖地区字段及尾字段。
- 商店：两个已标定普通商品槽的商品、库存与全局金币买卖价。完整 vendor 映射、神圣碎片和斗技场兑换表尚未开放。
- 六人编队：第六人功能和扩编荣誉费用。
- 类型克制：骑兵对步兵、弓兵对飞行、飞龙/狮鹫对骑兵三项倍率。

导出前会检查参数范围和模块间地址冲突。详细证据及仍需运行验证的风险见 [MOD 校准记录](MOD校准记录.md)。

导出包采用 `emulator/contents/<所选版本 Title ID>/<模块>/exefs/main.pchtxt` 结构，仅面向 Astris 等支持 `pchtxt` 的模拟器。Atmosphere 实机需要编译后的 IPS，当前不在导出范围内。

代码型补丁模板位于 `UnicornOverlord/mods/`；数据型补丁由 `ModPatchGenerator` 按参数动态生成。两者都只包含偏移与替换值，不包含游戏本体、RomFS、ExeFS、Keys 或 Firmware。新增写入前必须使用相同 Build ID 的主程序副本验证原值、字段宽度和写入范围。

## 最小验证

```bash
dotnet build UnicornOverlord/UnicornOverlord.csproj --configuration Release
dotnet run --project UnicornOverlord/UnicornOverlord.csproj -- --validate-mods .codex-melisandre-work/validation/all-modules.zip
```

第二条命令会用默认参数分别生成亚洲版和欧美版的全部十个模块，检查 ZIP 数量、Title ID、Build ID 和未替换占位符；欧美版文件名会自动增加 `-western`。界面验证至少覆盖：启动、打开存档副本、角色中文名称、职业选择窗口、物品与装备中文名称、保存工作副本以及自动备份。MOD 验证还需覆盖版本切换、模块导航、参数输入、模块启用状态、ZIP 路径和清单中的版本信息。
